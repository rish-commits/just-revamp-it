Just Revamp It

A dashboard is an instrument, and it is judged on one thing: whether a reader reaches a correct conclusion, fast, and knows how much to trust it. Every rule here serves that, and the ones that can be measured are measured rather than asserted.

01Brand

One accent in. A validated system out.

A handbook that says "swap the accent" is making a promise it cannot keep. Brands do not hand you a hue that happens to stay legible at every step of a sequential ramp. This derives the whole system from one colour and refuses to emit one that fails its own rules.

Try a hostile one. Green collides with the delta colour every dashboard reserves for improvement. Yellow is too pale to carry a 2px line on a near-white canvas.

02Principles

Four things, and only one of them is visual

  1. 01

    Restraint

    Good dashboards make few decisions and repeat them. A core of about five type sizes, four spacing steps, one accent. Sprawl is the most common cause of a dashboard that looks off while every individual choice is defensible.

  2. 02

    Judgment first

    Lead with the number and its verdict, then the detail. A surface that requires interpretation before it yields a conclusion has failed its reader.

  3. 03

    Light by default

    Dashboards are projected in lit rooms, screenshotted into light decks, and printed. Light grounds also give a sequential ramp more usable range, since every encoding here is a background fill. Dark is a narrow exception, not a preference.

  4. 04

    Earned trust

    Name the population every number counts. Define terms on the surface, not in a deck. Say what the data cannot say rather than drawing a clean shape that implies precision the source does not have. A dashboard caught overstating once is never fully believed again.

03Measured

Rules that can be checked, are

Four scripts, no dependencies. Prose gets argued about; a failing exit code does not.

palette.mjs

7

validations per accent, in both themes: ramp legibility, adjacent separability, colour-vision collapse, delta collision, canvas contrast, hero ink, heat ceiling.

vocabulary.mjs

0–100

restraint score. Grades the core vocabulary, the smallest set covering 90% of uses, so a disciplined system with a tail is not scored like an evenly-sprawling one.

scan.mjs

8

anti-patterns that make a reader draw a wrong conclusion: truncated baselines, invisible small values, missing tabular figures, undefined metrics.

specificity.mjs

0–100

was this built for this product, or any product? Invented data, template metric names, fabricated deltas, rainbow palettes, gradient text.

What the metrics found

Run against the production dashboard the system was extracted from: a core of four type sizes carrying 91% of uses, with a six-value tail. That distinction is the whole point. Counting distinct values alone would have scored a disciplined system as chaos.

The specificity detector scores that same hand-built dashboard 89, and a synthetic generated one 0. The tell is never ugliness. Generated dashboards are tidy. The tell is that they know nothing about the product: borrowed metric names, invented figures, and a palette that encodes nothing.

04Rules

Six that change what people believe

Not style preferences. Each of these changes the conclusion a reader draws.

Growth from a zero baseline

Reports fake growth

↑ 100%

Last period was zero. There is no meaningful percentage change from nothing, and the number is spectacular by construction.

Renders nothing

14 · first period

The delta is null and the badge does not appear. The kit enforces this: the component returns nothing rather than inventing a percentage.

A funnel step worth 0.3% of the first

Reads as absent

A proportional width renders a real value as nothing at all, so a reader concludes the step has no users rather than few.

Floored, and still true

Non-zero fills floor at a visible minimum. A true zero draws no bar at all, because those are different statements and must look different.

A step that did not move

Silent blank

Suppressing the change when it is zero looks identical to failing to compute it. A reader cannot tell flat-by-design from broken.

Prints it

0%

And a step above 100% is shown, not clamped. It means the population is not a subset of the one above, which is real information about your instrumentation.

Which step is leaking

Largest percentage drop

Picks a trivial step off a tiny base and sends the team to fix a problem affecting nine people while ten thousand leak elsewhere.

Largest absolute drop

Exactly one step flagged, in the change text only, never by recolouring the bar. Steps whose conversion is not a true per-user rate are excluded entirely.

A metric with no population

Two readers, two numbers

Active users  1,204

Active out of whom? Everyone in the database, everyone real, or everyone who finished onboarding? Each is a different figure.

States what it counts

Active, onboarded  1,204

A number without its population is a wrong number. The denominator of a rate is a population too, and it is usually the one people get wrong.

Direction carried by colour

Says nothing to 8% of men

A coloured magnitude with a decorative arrow carries no direction at all for a reader with red-green colour blindness, and green and red are the classic collision.

Glyph and text too

No fact is carried by hue alone. Direction gets a glyph and a word in the accessible name; status gets a word; category gets a direct label.

06Install

Two lines

/plugin marketplace add rish-commits/just-revamp-it
/plugin install just-revamp-it@just-revamp-it

Then /just-revamp-it audit in any repo. With no argument it audits, then offers critique and revamp.

Or run the scripts directly

node scripts/palette.mjs "#7c3aed" --css     # derive + validate tokens
node scripts/vocabulary.mjs ./src            # restraint score
node scripts/scan.mjs ./src                  # anti-patterns
node scripts/specificity.mjs ./src           # generated, or designed?

Plain Node, no dependencies. palette.mjs exits non-zero on failure, so it drops straight into CI.

07Provenance

Where these rules came from

Extracted from one production product-analytics dashboard: a few hundred users, one timezone, one currency, one accent hue, one export target, short funnels, and a deliberately single-theme interface.

Chapters covering what that dashboard shipped are evidenced by practice. Chapters covering what it never had to solve are reasoned from the same grammar: sound, but unproven. Both are marked.

Do not mistake a single-instance decision for validated law. When a rule does not survive contact with real data, that is information the system owner needs, not a reason to quietly drop it.
